# 聪明钱雷达

国家资本与产业资本动向的日更工具。输入是一堆官方/半官方数据源，输出是**带溯源的、可验证的一句话**。

## 一句话长什么样

```
央行2026-10黄金储备 7,830 万盎司，环比 +83 万盎司（+25.8 吨），
连续第 9 个月增持；年内累计 +411 万盎司（+127.8 吨）；
按当月 3,885 美元/盎司估算，本月购金耗资约 32 亿美元（沪金 854.8 元/克）。
[源:SAFE官方储备资产|置信:高|滞后:0天]
```

```
梧桐树投资平台 13F 2026-03-31→2026-06-30：持仓 4→5 只，市值 120→379 亿美元；
新建仓 1 只（最大 SPACE EXPLORATION TECHN CORP 263.4 亿美元）
[源:SEC 13F|置信:高|滞后:45天]
```

```
2026-11-06 大宗交易 45 笔，成交 7.98 亿元；机构专用席位买入 20 笔 4.16 亿元
（占比 52%），折价成交 34 笔。机构最大买入：华夏沪深300ETF（510330）1.53 亿元。
[源:东方财富大宗交易|置信:高|滞后:1天]
```

## 三道闸

1. `upsert_fact()` 无 `source_url` 直接抛错 —— 杜绝无源结论
2. 每条句子强制带 `[源|置信|滞后]` 尾巴
3. CHANGE（今日变化）与 STATE（当前状态）分离 —— 日报只讲变化

## 用法

### 浏览器界面（推荐）

```bash
python -m smartmoney.web                # http://127.0.0.1:8848
python -m smartmoney.web --port 9000    # 换端口
python -m smartmoney.web --host 0.0.0.0 # 局域网可访问
```

界面分十块：**总述 → 今日一句话 → 聪明钱下场买了什么 → 央行黄金储备 → 资产行情 → 13F 持仓 → 大宗交易与增减持 → 区域房价指数 → 公告扫描 → 数据源健康**。
右上角「重新采集」直接触发一次全量抓取，跑完自动刷新视图。

接口（都是 JSON，可直接接别的程序）：

| 方法 | 路径 | 内容 |
|---|---|---|
| GET | `/api/summary` | 总述 + 一句话信号 + 数据源健康 + 统计 |
| GET | `/api/smartbuy` | **聪明钱买入清单，按阵营（北向/汇金/社保/国资/险资/外资/公募）分组** |
| GET | `/api/gold` | 黄金储备时序，含环比、当月金价、购金成本估算 |
| GET | `/api/assets` | 多资产行情：贵金属/工业金属/能源/股指/汇率/债券 |
| GET | `/api/region` | 70 城房价指数，分城市同比环比 |
| GET | `/api/holdings` | 13F 持仓明细 + 上期对比 + 清仓名单 |
| GET | `/api/trades` | 大宗交易（按额排序）+ 高管增减持 |
| GET | `/api/announcements` | 公告扫描，带否定式/关键主体标记 |
| POST | `/api/collect` | 触发采集（同步，约 60 秒） |

### 命令行

```bash
python -m smartmoney.cli run              # 全量采集 + 出报

```

## 「聪明钱下场买了什么」怎么做的

这是本工具的核心板块，也是最难的一块。走过三条弯路：

1. **从公告标题抽金额** —— 失败。标题只有「关于收购XX股权的公告」，金额全在 PDF 正文里。
2. **找东财并购重组报表** —— 不存在。`RPT_MA_DEAL`、`RPT_ACQUISITION`、`RPT_SHARE_TRANSFER` 全部「报表配置不存在」。
3. **用十大流通股东** —— 成了。

`RPT_F10_EH_FREEHOLDERS` 字段：

- `HOLDER_NAME` 谁（含「香港中央结算」「社保基金17022组合」「中央汇金」等）
- `SECURITY_NAME_ABBR` 买了什么
- `HOLDER_STATE` **动作**，取值 `新进` / `加仓` / null
- `HOLDER_MARKET_CAP` 持仓市值
- `HOLD_NUM_CHANGE` 变动股数
- `END_DATE` 报告期

按股东名称特征归入 8 个阵营：北向资金、汇金证金、社保养老金、国资平台、险资、外资、公募、其他机构。

**两个必须记住的坑：**

- **`香港中央结算有限公司` 就是北向资金**（沪深港通）。第一版把它归进「其他机构」，等于把最大的一条外资线索扔了。修好后北向立刻成为最大阵营（41 笔 97.7 亿美元）。
- **排序不能按 `HOLDER_MARKET_CAP`**。按市值排会先把 2009、2015 年的汇金持仓（建设银行 9300 亿）捞出来。必须 `sortColumns=END_DATE&sortTypes=-1`，再按时间窗口筛。

## 数据源坑位（实测踩过的，别再踩）

- **SAFE**：详情页 HTML 无表格，数据在 xlsx 附件。附件链接抓 `/safe/file/file/...xlsx`。表头列是 `项目 | 2026.01 | (空) | 2026.02 ...`，月份占奇数列；黄金储备量在单独一行（首列为空，值形如 `7419万盎司`）。**必须按列索引对齐**，不能按非空值顺序取 —— 否则会把「亿美元」列当成黄金量，直接产出错误数字。
- **巨潮**：`hisAnnouncement/query` 返 0 字节，必须用 `fulltextSearch/full` + POST 表单 + `Referer`。
- **HKEX DI / HKEXnews**：`di.hkex.com.hk` 返 1137 字节壳页（Akamai 拦截，带 `bm_s`/`bm_so` cookie 仍挡）；`www1.hkexnews.hk/titleSearchServlet.do` 能建会话但 `recordCnt=0`。需 headless browser。目前海外腿走 SEC 13F 替代。
- **中国政府采购网**：连续请求触发「您的访问过于频繁」，返 2749 字节拦截页。需限速 + 换 IP。
- **东财**：`DEAL_AMT` 是人民币元，接口不给美元，汇率自己换。
- **13F**：`primary_doc.xml` 直接拼路径 404。正确走法是先取 `index.json`，从中找 `informationtable.xml`。报告期 `periodOfReport` 格式是 `MM-DD-YYYY`，要转 ISO。

## 量化能力分级

**A 级（能出准确数字）**
央行黄金储备、金价、13F 持仓市值、大宗交易金额、高管增减持金额。

**B 级（只能出区间）**
央行购金成本 —— 月度增量 × 当月均价，误差 ±3%。央行不公布成交价，这是理论上限。

**C 级（只能出方向）**
家族办公室离岸层、代持、非上市股权。不要试图量化，会得到假精确。

## 已知缺口

- **收房（存量商品房收储）没有全国统一数据源。** 现行的「收储」公告 99% 是政府从企业手里收**土地**，不是从居民手里收**商品房**。两者在标题里都写「收储」，是最容易混淆的坑。当前 `rule_shouchu` 已做区分并标 `置信:中`。
  可行替代：各省公共资源交易中心 + 财政部地方债项目清单 + 央行 PSL 余额，需按城市逐个接，工程量大于其余全部源之和。
- **PSL / 保障房再贷款余额**在央行货币政策执行报告 PDF 里，需 PDF 解析，未接。
- **港股权益披露**被 Akamai 挡，需 headless browser。
